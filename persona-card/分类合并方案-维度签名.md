# 分类合并方案 · 维度签名驱动（8 题材党 × 10 主角原型）

> 目标：把"8 个题材党"和"10 个主角原型型"合并为一套由「维度签名」驱动的分类。
> 核心改动：四维不再精算距离，只判断每个维度 **HIGH / LOW**（阈值建议 65），用"哪几个维度高"来定结果。

---

## 一、为什么这么改

原 `matchArchetype` 用四维欧氏距离精确匹配。问题：真实用户常出现**行动+理性+共情都高**、甚至**四维全高**，精确分区分不出这种"多高"人群，而且分差几格就跳到另一个原型，结果发飘。

→ 改为**维度签名**：每个用户 = 一个 HIGH 维度集合，例如 `{行动,理性,共情}`、`{共情}`、"四维全高"。结果卡写成「你是【重生复盘党】的【前世清算型】」，天然贴合知乎"你是XX型"的体感。

## 四、你提到的「3 高 / 4 高」怎么落

- **已覆盖**：`{行动,理性,共情}`、`{行动,理性,自由}` 两个 3 高直接命中现有原型。
- **缺口**（目前没有专属原型）：
  1. `{行动,自由,共情}`（暖心行动派）
  2. `{理性,自由,共情}`（解构+共情派）
  3. **四维全高**（全能派）
- **两种处理思路**：
  - **A｜新增 1 个"全能操盘型"** 专门接"四维全高"，两个缺口 3 高暂并入最近的现有型（暖心→温柔兜底型；解构共情→真相解构型）。原型总数变 11。
  - **B｜不新增**，四维全高的人按"最高那维"先归单高型，再标"全能版"后缀（如「硬核秩序型·全能版」）。原型保持 10 个。

## 五、改名后的匹配逻辑（伪代码）

```js
const THRESHOLD = 65;
function classify(scores) {
  const HIGH = AXES.filter(a => scores[a.key] >= THRESHOLD).map(a => a.key);
  // 1) 精确签名命中（含主导维 tiebreak）
  const hit = MASTER.find(m => matchSig(m.sig, HIGH, scores));
  // 2) 未命中（罕见 3 高 / 4 高）→ 取 HIGH 的超集或最近签名
  const fallback = hit || MASTER.nearest(HIGH);
  return { genre: fallback.genre, archetype: fallback.archetype };
}
```
